Restaurant lookup
- Any restaurant name can be recognized and researched; there is no restaurant allowlist.
- India is the default market, with explicit India-domain queries and country checks.
- Pages and linked nutrition PDFs are read; search snippets are not nutrition evidence.
- Published matches require row/header/serving evidence and a second reasoning check.
- Unverified nutrition blogs cannot establish a published menu match.
- Public-page cache: at most 100 pages, 7-day expiry, original read date shown when used.
- Missing or conflicting evidence produces a labelled estimate or clarification.
- Website blocks, missing menus, model errors and portion variation prevent a guaranteed
  10 percent error tolerance. This release has no measured population accuracy benchmark.

Operations
Use deploy.sh on the configured server. It builds the checked-out revision, retains
persistent data, performs startup checks and restores the previous image on failure.
Do not start a second polling instance with the same Telegram token.
Credentials belong in the private .env file and are excluded from Git and Docker builds.
Personal meal databases, public-page cache files and source snapshots are not committed.
The repository default branch is not automatically changed by deployment.

Multi-user readiness
The bot remains owner-only. See MULTI_USER_ASSESSMENT.txt before enabling invitations.
Explicit usuals/corrections are saved personal memory; this is not automatic model training.
